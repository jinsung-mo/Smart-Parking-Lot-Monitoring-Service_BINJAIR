# 빈자리 (BINJARI)

**주차장 영상을 분석해 어느 주차면이 비어 있는지 앱에 알려주는 서비스입니다.** 출발 전에 빈자리 수를 확인하고, 도착한 뒤에는 주차면별 상태를 볼 수 있습니다. 저장한 기록으로 시간대별 혼잡도도 안내합니다.

| 항목 | 내용 |
| --- | --- |
| 기간·인원 | 2024.12 ~ 2025.06 · 창원대학교 컴퓨터공학과 캡스톤 디자인 · 2인 팀 |
| 구현 범위 | 55호관 20면, 도서관 36면 · 총 56개 주차면 |
| 수상 | 교내 소프트웨어 전시회 인기상 |
| 제 담당 | Flask 서버, 영상 추론 주기 조정, 주차면 상태 판정, SQLite 저장·통계 |
| 사용 기술 | Python, Flask, OpenCV, YOLOv8x, SQLite · 앱은 Flutter |

## 왜 만들었나요?

주차장 위치를 알아도 빈자리가 어디 있는지는 직접 돌아봐야 합니다. 주차면마다 센서를 설치하는 대신, 카메라 영상에서 빈자리와 점유 영역을 찾아 앱에 표시하는 방식으로 만들었습니다.

사용자는 캠퍼스 지도에서 주차장을 고르고 현재 빈자리 수와 주차면별 색상을 확인합니다. 시간대별 점유율은 기록이 있는 시간만 표시해 방문 시간을 고르는 데 참고하도록 했습니다.

## 제가 맡은 일

저는 팀원이 학습한 모델의 탐지 결과를 **주차면별 상태로 바꾸는 서버**를 만들었습니다. 영상 입력과 추론 간격을 관리하고, 탐지 영역을 주차면에 연결한 뒤 상태를 저장해 앱 API로 전달했습니다. 앱 개발과 모델 학습은 안서현이 맡았습니다.

| 이름 | 담당 |
| --- | --- |
| 모진성 | Flask 서버, 주차면 매핑과 상태 판정, SQLite 저장·통계 |
| 안서현 | Flutter 사용자·관리자 앱, 주차면 탐지 모델 학습 |

## 문제 해결

### 탐지 박스 하나를 주차면 하나로 셀 수 없었습니다

모델이 찾은 영역은 옆 주차면까지 걸치거나 하나의 주차면에 겹칠 수 있습니다. 탐지 개수만 세면 앱의 빈자리 수와 맞지 않았습니다.

먼저 영상 위에 주차면 경계를 다각형으로 등록했습니다. 각 주차면과 탐지 박스의 교차 면적을 주차면 면적으로 나누고 탐지 신뢰도를 곱해 연결 점수를 구했습니다. 최근 판정까지 반영한 뒤 확정된 상태를 DB에 저장합니다.

이 겹침 비율은 교차 면적을 **주차면 면적**으로 나눈 값입니다. 두 영역의 합집합을 쓰는 IoU와는 다릅니다. [주차면 연결 코드](app_v1.py#L1132-L1155)

### 잠깐의 탐지 누락이 빈자리 안내로 바뀔 수 있었습니다

차량이 가려지거나 신뢰도가 낮아질 때 한 프레임만으로 상태를 바꾸면, 주차된 면을 빈자리로 안내할 수 있습니다. 운전자가 그 자리까지 갔다가 다시 찾아야 하므로 빈자리로 바꾸는 쪽을 더 조심하도록 했습니다.

최근 10개 판정에 시간과 신뢰도 가중치를 적용한 뒤, 일반 주차면은 점유 전환을 5회, 빈자리 전환을 8회 확인합니다. 상태 머신의 신뢰도 기준은 0.7입니다. 이렇게 여러 번 확인하면 실제 출차도 늦게 반영될 수 있습니다.

카메라 가장자리의 55호관 B1에는 별도 기준을 적용했습니다. 공개한 B5 영상에서는 상태 전환을 확인했지만, 전체 주차면의 오탐률 감소까지 측정하지는 않았습니다. [시간 필터와 상태 머신](app_v1.py#L1225-L1405)

### 비슷한 프레임에 같은 추론을 반복했습니다

주차 상태는 연속된 프레임 사이에서 크게 달라지지 않는 경우가 많았습니다. 5프레임 중 1개만 모델로 분석하도록 바꿔 추론 대상 프레임을 설정상 약 80% 줄였습니다.

영상 읽기와 전처리는 여전히 필요하고, 앱도 다음 조회까지 기다려야 합니다. 따라서 80%는 추론 대상의 감소율이며 전체 처리 시간이나 앱 반영 속도의 개선율로 사용하지 않습니다. [프레임 처리 코드](app_v1.py#L695-L704)

## 프로젝트 종료 후 수정한 부분

기존 코드와 시연을 다시 확인하면서 다음 내용을 개인적으로 보완했습니다.

| 문제 | 수정 |
| --- | --- |
| 기록이 없는 시간에도 임의 값으로 혼잡도가 표시됨 | 5분 간격 관측 기록을 집계하고, 당일 평균이나 최근 7일 평균이 있는 시간만 표시. 기록이 없으면 `has_data=false`로 구분 |
| 두 주차장이 같은 주차면 ID를 사용함 | 상태 테이블 기본키를 `(parking_lot, id)`로 바꿔 주차장별 상태를 구분 |
| 모델 판정과 앱 표시를 함께 확인하기 어려움 | 실제 추론 기록을 API로 재생하고 기존 Flutter 상세 화면의 상태 변화를 녹화. 재생 서버 테스트 추가 |

시간 추천은 향후 12시간 중 관측 기록이 있는 시간대의 점유율을 비교합니다. 미래 혼잡도를 예측하는 AI 모델은 사용하지 않습니다. [통계 집계](app_v1.py#L1602-L1689) · [재생 서버 테스트](tests/test_inference_replay.py)

## 시스템 구성

![영상 입력에서 탐지와 주차면 판정, SQLite 저장, Flask API, Flutter 앱으로 이어지는 구조](docs/images/system-architecture.svg)

영상 분석과 API를 Python에서 함께 다루기 위해 Flask와 OpenCV를 사용했습니다. 상태와 이력은 한 분석 서버의 SQLite에 저장했습니다. 별도 DB 서버 없이 시작할 수 있었지만, 주차장과 쓰기 작업이 늘면 잠금과 대기 시간을 확인해야 합니다.

모델 탐지 박스를 주차면 상태로 바꾸는 계산과 필터는 서버가 담당하고, 앱은 API에서 현재 상태와 통계를 받아 표시합니다. 카메라 위치가 달라지면 주차면 좌표도 다시 등록해야 합니다.

## 남은 과제

현재 공개 시연은 주간 영상 두 개입니다. 야간·우천·차량 가림 조건별로 정답 데이터를 마련해, 점유면을 빈자리로 안내하는 비율과 상태 전환 지연을 측정할 필요가 있습니다.

학습 당시 YOLOv8x의 `mAP@50`은 97.42%입니다. 물체 탐지 지표이므로 최종 주차면 상태를 같은 비율로 맞혔다고 볼 수는 없습니다. 공간 매핑과 시간 필터를 포함한 서비스 판정은 별도로 평가해야 합니다. [모델 평가 조건](docs/MODEL.md#사용한-모델)

앱의 10초 조회 간격도 추가 지연을 만듭니다. 모델 실행, 상태 확정, 앱 표시 시각을 나눠 측정한 뒤 조회 간격이나 변경 알림 방식을 조정하려고 합니다.

## 실행 방법

### 분석 서버

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

export MODEL_PATH="$PWD/models/best_seo.pt"
export ADMIN_TOKEN="change-me"
python app_v1.py --no-video
```

기본 포트는 5000입니다. 모델 가중치는 Git 저장소에 포함하지 않으므로 별도로 준비해 `MODEL_PATH`에 지정합니다. 입력 영상은 `VIDEO_PATH_A`, `VIDEO_PATH_B`로 설정합니다. [모델·시연 재실행 안내](docs/MODEL.md)

### Flutter 앱

```bash
flutter pub get
flutter run --dart-define=API_BASE_URL=http://<서버 IP>:5000
```

Google Maps 키는 Android의 `android/local.properties`, iOS의 `ios/Flutter/Secrets.xcconfig`에 `MAPS_API_KEY`로 설정합니다. 실제 기기에서는 서버의 LAN IP를 사용합니다.
